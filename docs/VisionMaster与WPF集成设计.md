2026-10-21 更新：阶段 7B 已实现可识别标定对象与六轴固定相机九点采样。当前版本 AxisLab 0.7.0 / WPF 1.2.0。范围、验证及 SDK 授权限制以[阶段 7B 验收](阶段7B验收记录.md)和[操作教程](VM九点标定与WPF集成教程.md)为准。下文保留阶段规划与历史记录。

需求基线：2026-10-21。用户选择“图像源＋SDK”：调试时在 VisionMaster 使用仿真图片，集成时由 WPF 获取 AxisLab 图像并送入 VisionMaster SDK。现有 Blockly 不再作为后续教学主线；已有工程和功能保留。

框架调整：用户随后提供 WpfDemo/WpfDemo 源码，当前以该项目为主线。AxisLab.WpfDemo 1.1.0 保留原 .NET 9 白色三栏界面，通过同用户命名管道调用独立 .NET Framework 4.8 VM 进程。早期原型采用单独的 .NET Framework WPF，现作为历史验证保留。见[原框架使用说明](原WPF框架集成说明.md)与[验收记录](原WPF框架集成验收.md)。

## 目标与职责

| 程序 | 职责 |
| --- | --- |
| AxisLab | 仿真机器人、相机、场景、成像、机器人状态及运动；后续补充标定板和可识别对象 |
| VisionMaster | 用户自行搭建图像处理、定位、标定、坐标映射流程，并保存 .sol 方案 |
| WPF Demo | 选设备、触发拍照、送图给 VM、运行指定流程、读取结果、记录样本、预检并控制机器人 |

数据链：AxisLab PNG＋曝光时机器人姿态 → WPF → VM SDK 图像源 → 用户流程 → 标定/定位结果 → WPF → AxisLab 运动预检及执行。

VM 中的流程编辑由用户完成。WPF 加载用户保存的方案；首版采用独立原图预览及数值结果展示，不承诺嵌入完整 VM 流程编辑器。图像源采用 SDK，不实现 GigE Vision/USB3 Vision 相机枚举。

## 本机基线

- 已发现 VisionMaster 4.3.0，目录 C:\Program Files\VisionMaster4.3.0。
- 安装包内 .NET SDK 指南为 V4.3.1；以实际程序集及官方示例签名为准。
- 官方 WPF 示例目标为 .NET Framework 4.8。当前保留用户 .NET 9 WPF 主进程，SDK 在独立 Windows x64/.NET Framework 4.8 进程运行，不跨运行时直接加载厂商程序集。
- AxisLab 和 WPF 分别运行，通过现有 HTTP/Modbus 接口连接；不修改本机 VM 安装文件、注册表或已有方案。
- VM 运行环境及相关授权由本机提供。发布 Demo 不附带厂商 SDK、算法包或授权文件。

## 图像及标定数据

1. WPF 选择相机 UUID、机器人 UUID，触发一次捕获并取得 CaptureId。
2. 等待该 CaptureId 完成，读取固定 FrameId 的 PNG，验证 SHA-256。
3. 从同一曝光帧取得对应机器人关节、法兰和 TCP 位姿，不能事后读取当前姿态替代曝光姿态。
4. 解码 PNG 为紧凑 RGB24 或 MONO8 像素，送给指定图像源；保持缓冲区到执行结束。
5. 每张采样图独立命名，保存 PNG 与 observation.json。用于标定的样本仅保存图像、帧身份、尺寸及机器人可测姿态，不把相机真实安装或真实内参作为算法输入。
6. 相机安装、分辨率、机器人几何、工具或工作坐标改变时，重新绑定并验证用户标定方案。

VM 调试先使用导出的 PNG；集成后将同一个图像源设为 SDK 模式，由 Demo 送图。模块名和流程名必须与用户方案一致。

## 首个运动闭环：固定相机平面定位

先从固定相机、已知高度平面和单个目标开始。用户在 VM 建立 N 点标定/坐标映射和定位流程，输出机器人基座下的 X、Y、Rz。WPF 显式设置目标 Z、Rx、Ry，预检成功后再运动。像素坐标不能直接作为机器人毫米坐标使用。

建议的流程输出契约：

流程另需一个整数输入 AxisLabRequestId。WPF 每次送图分配新请求编号，VM 本次流程完成后通过整数输出 ResultRequestId 回传同一个编号；不匹配则丢弃结果。

| 输出名 | VM 类型 | 语义 |
| --- | --- | --- |
| ResultRequestId | 整数，恰好 1 个值 | 本次 AxisLabRequestId，完成本帧处理后回传 |
| CalibrationOk | 整数，恰好 1 个值 | 1 表示用户流程当前使用的标定有效 |
| TargetOk | 整数，恰好 1 个值 | 1 表示本帧恰好得到一个有效目标 |
| RobotX | 浮点，恰好 1 个值 | 机器人基坐标 X，mm |
| RobotY | 浮点，恰好 1 个值 | 机器人基坐标 Y，mm |
| RobotRz | 浮点，恰好 1 个值 | 基坐标下目标 TCP 的 Rz，deg；由流程完成角度约定和偏置 |

这些是本项目约定的自定义流程输出名，不是 VM 自带的固定接口。WPF 提供字段映射。缺结果、多目标、NG、非有限数、旧帧、设备/方案变化均不得产生新的运动。不同工件高度、任意三维姿态、末端相机需要后续的模型和手眼变换，不能由这一个平面闭环替代。

WPF 的“标定方案标识”用于绑定和追溯用户已完成的 VM 方案，不表示 Demo 自己完成了标定求解。VM 的标定系数保留在用户 .sol 中；后续支持独立结果文件和标定报告。

## Demo 操作效果

- 连接区：AxisLab 实际 HTTP 地址、相机和机器人选择、连接状态。
- 方案区：VM .sol 路径、密码、流程名、图像源名、像素格式和输出字段。
- 图像区：AxisLab 原始图像、帧号、曝光时间及拍摄时机器人姿态。
- 标定区：采样保存目录、保存配对样本；后续增加九点采样表、手眼采样表和独立验证。
- 定位区：标定方案标识、已知目标 Z/Rx/Ry、速度、机器人目标、预检结果。
- 操作：拍照、保存样本、运行 VM、绑定标定方案、预检、执行一次、停止。

首版不自动循环运动。只有新一次检测及预检成功才能执行；停止和窗口关闭取消本 Demo 的任务。Modbus 运动保持原有控制权、变化心跳及会话/序号规则。

## 重新划分的阶段 7

| 里程碑 | 交付 | 验收 |
| --- | --- | --- |
| 7A 外部接入底座 | WPF 取图、SDK 送图、加载用户 .sol、读取约定结果、样本导出及运动桥接 | 同一仿真帧进入 VM；结果由用户流程产生；无结果不运动 |
| 7B 标定练习场景 | 可添加标定板/特征对象，固定相机九点采样，配对表、用户标定文件和验证点 | 用户在 VM 建流程完成平面标定，换位置仍能定位 |
| 7C 固定相机定位闭环 | 检测结果映射、接近高度、姿态偏置及定位误差报告 | WPF 检测后机器人到达实际目标，独立点检验 |
| 7D 末端相机及完整手眼 | 多姿态采样、姿态约定、变换链和失效追踪 | 用户以 VM 实际支持的模块或外部算法完成求解；不能把 N 点平面映射称为完整三维手眼 |
| 7E 双相机和多坐标 | 工位/工件关系、多方案绑定、异常及独立验证 | 相机结果和标定相互隔离，工位移动后按识别更新 |

阶段 8 延续夹爪、传送带、光电及完整抓放。最终由用户的 WPF 程序编排，通过 VM 检测和 AxisLab 仿真完成练习。
