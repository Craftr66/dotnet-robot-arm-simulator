# AxisLab.WpfDemo 1.1.0 原框架集成验收

日期：2026-10-21。源码来自用户指定的 原 WpfDemo 工程目录。原目录先按文件 SHA-256 留存基线，再在工作区修改验证；回写前再次核对基线并备份原文件。

## 交付范围

保留原 .NET 9 WPF 白色三栏界面、工程选择、三轴/六轴关节控制、控制权/心跳、相机触发取图及日志。右侧增加 VisionMaster、标定定位页。通过独立 .NET Framework 4.8 进程调用本机 VM 4.3.0，主程序不直接加载厂商程序集。

新增流程输入输出映射、请求身份校验、RGB24/MONO8 送图、曝光图像与机器人完整矩阵配对导出、用户方案绑定、固定相机平面目标预检及 Modbus 操作码7单次运动。修复原停止操作与运动共用连接门锁、旧框架不能解析长积木 JSON、同步断开时窗口关闭重入的问题。

## 验证证据

WPF 与 VM Bridge Release 构建均为0警告、0错误。执行 `node scripts/wpf-framework-checks.mjs`，39项通过。构建版证据：`artifacts/wpf-framework-checks/1792570877193/results.json`。

最终发布目录通过设置 `AXISLAB_WPF_EXE=dist/AxisLab.WpfDemo-1.1.0-win-x64/AxisLab.WpfDemo.exe` 再跑同一套联调，39项全部通过，主程序正常退出（0）。发布版证据：`artifacts/wpf-framework-checks/1792571445911/results.json`；同目录有三个页面截图与配对样本。测试未使用开发版Worker覆盖路径；主进程指向不存在的DOTNET_ROOT，并关闭多级运行时查找，确认自带.NET9.0.20运行时与发布目录内的VM Bridge可协作。VM Bridge仍依赖本机.NET Framework4.8及VM运行环境。

测试使用隔离工程目录、独立 HTTP/Modbus 端口与无头 Edge 渲染，不连接或停止用户已有的 AxisLab 实例。

## 已知边界与下一步

尚未收到用户自己的标定/识别.sol。官方CircleFind方案仅用于验证SDK加载和送图，不含本项目约定的请求输入和机器人坐标输出，因此它的“送图并运行”预期报缺字段，不能驱动机器人。

当前绑定只追溯用户已完成的标定，不计算标定系数。定位限定固定相机、已知平面、单目标、机器人基坐标MoveJ；末端相机仅取图和送VM。完整手眼、工件坐标求解、标定板/九点采样、双相机与传送带仍待后续阶段。

下一步：实现标定对象及采样向导，用户在VM中建立映射与识别.sol，再用未参与标定的点验证坐标误差和单次定位。
