# AxisLab 0.6.0 外部连接快速开始

日期：2026-10-21。软件是 Modbus TCP 服务端，外部 C# 程序、PLC 或调试工具作客户端。机器人动作、状态和拍照指令通过 Modbus；PNG 通过 HTTP 获取。

## 1. 打开软件和示例

先保存并退出旧版，再运行完整发布文件夹中的 `AxisLab.exe`。导入 `Samples/external-control.scene.json`。该示例设备编号为：

| 编号 | 设备 | 说明 |
| --- | --- | --- |
| 1 | 通用三轴 3R | 底座 Z、肩 Y、肘 Y，三个旋转关节 |
| 2 | 通用六轴 6R | 原有六轴模型 |
| 3 | 固定全景相机 | 独立安装 |
| 4 | 法兰相机 | 挂载到三轴机械臂 |
| 5、6 | 工作台、工件 | 几何体 |

自建工程的编号以“对象属性 → 设备编号”或设备列表为准，不能假设机器人永远是 1。重命名不会改变编号，复制产生新编号，删除的编号不复用。工程关闭再打开会产生新通信会话，外部客户端应重新选择设备。

三轴和六轴可同时存在，关节、尺寸编辑、回零/停止、法兰/TCP 和末端相机都按实际轴数工作。三轴不能独立调整完整六维末端姿态；当前支持位置 IK、MoveL、五次时间插补和基础碰撞检测；六轴另支持完整位姿目标。新增操作见《运动与示教使用说明.md》及《运动与示教接口.md》。

## 2. 查看连接地址

点击顶部“外部连接”，或原生菜单“工具 → 连接信息 / 复制全部连接信息”。

| 项目 | 默认值与用途 |
| --- | --- |
| HTTP | `http://127.0.0.1:本次端口`，设备列表、运行状态、协议映射、帧信息和 PNG；桌面端口由系统分配 |
| Modbus TCP | `127.0.0.1:1502`，设备发现、状态、控制权、关节动作、停止和拍照 |
| Unit ID | 1 |
| 功能码 | 03 读保持寄存器、06 写单寄存器、16 写多寄存器 |
| 地址模式 | 十进制零基 PDU 偏移；某些软件显示 40001 对应本文地址 0 |
| 数据顺序 | 每寄存器高字节先；UInt32/UInt64/Float32 高字在前，Float32 为 ABCD |

HTTP 和 Modbus 是两个端口。C# 示例从 HTTP 查询实际 Modbus 端口，避免手写错误。默认仅本机连接；另一个电脑连接的方法见第 5 节。

## 3. 用独立 C# 程序连接

编译示例需 .NET 10 SDK；运行 AxisLab 本体不需要 SDK。发布包已附 `Samples/ModbusClient` 源码，无额外 NuGet 依赖。在发布文件夹打开 PowerShell，将下面地址替换为软件显示的 HTTP 地址：

```powershell
$axisUrl = 'http://127.0.0.1:53120' # 示例端口，替换为本次实际值

# 通过 Modbus 发现设备，HTTP 补充可读名称
dotnet run --project .\Samples\ModbusClient -- $axisUrl list

# 读取三轴设备状态、角度与 TCP
dotnet run --project .\Samples\ModbusClient -- $axisUrl state 1

# 三轴：三个角度，单位 deg；末尾是速度百分比
dotnet run --project .\Samples\ModbusClient -- $axisUrl move 1 20,-10,30 25

# 六轴：六个角度
dotnet run --project .\Samples\ModbusClient -- $axisUrl move 2 10,0,0,0,0,0 25

# 停止指定机器人，撤销其外部控制权
dotnet run --project .\Samples\ModbusClient -- $axisUrl stop 1

# 通过 Modbus 触发相机 3，再通过 HTTP 下载对应 PNG 和帧 JSON
dotnet run --project .\Samples\ModbusClient -- $axisUrl capture 3 .\captures
```

源代码项目根目录使用 `samples/ModbusClient` 路径。示例 `Program.cs` 演示业务流程，`ModbusTcpClient.cs` 演示 MBAP、FC03/FC16、网络读取和字序。移动示例自动申请控制权、每秒递增心跳、等待完成并释放；相机示例核对帧 SHA-256。终端输出失败信息并返回非零退出码，不伪装成功。

拍照需要保持 AxisLab 渲染窗口打开，并等待“相机成像就绪”。机械臂状态和运动本身不依赖渲染器。PNG 与帧 JSON 要主动保存，图像缓存不写入工程。

## 4. 使用通用 Modbus 工具或自行编写客户端

完整地址表在《ModbusTCP操作协议v1.md》，机器可读映射在 `Modbus-v1-map.json`，也可在“外部连接”对话框导出。按以下顺序操作：

1. 连接实际 Modbus 地址，Unit ID=1。FC03 从 0 读 32 个寄存器，核对 0=`0x4158`、1=1，保存 4—7 的项目会话令牌。
2. 将设备编号写入 200（FC06 或 FC16 单寄存器）。从 0 读 120 个寄存器，检查 29=1、13=实际轴数，并保存 98—99 配置版本。所有选择、暂存、结果窗口都属于当前 TCP 连接。
3. 在 202—229 暂存命令参数，包括操作码、预期会话令牌和配置版本。先申请机器人控制权：操作码 1。
4. **最后**用一次 FC16 写 232—233，提交非零、递增的 UInt32 序号。这个写入才触发执行。不要逐个写提交序号的两个字。
5. 读取 15、16、18—25：3=成功完成，2=运行，4/5/6=失败/取消/拒绝。动作期间每秒用一次 FC16 写 230—231，心跳计数必须改变；5 秒没有新计数自动停止并释放控制权。
6. 移动使用操作码 3，204 填 3 或 6，206—217 填目标 Float32，218—219 填速度 Float32。三轴未使用的 J4—J6 必须为零。完成后操作码 2 释放。
7. 拍照使用操作码 5，无需申请机器人控制权；成功后 24—25 得到 frameToken，用曝光时工程会话查询 HTTP 帧映射并下载图像。

同一连接一次只能选择一个设备，持有控制权或有活动任务时不能切换。不同连接可以读同一个机器人，但同一机器人只有一个控制者；不同机器人可分别控制。停止指令不要求控制权；界面“停止运动”也可以撤销外部控制。

## 5. 让另一台电脑连接

默认监听 `127.0.0.1`。需要跨电脑时，先保存并关闭 AxisLab，再在发布文件夹用以下方式启动：

```powershell
$env:AXISLAB_LISTEN_ADDRESS = '0.0.0.0'
$env:AXISLAB_MODBUS_PORT = '1502'
& '.\AxisLab.exe'
```

也可将 `0.0.0.0` 换为此电脑指定网卡的 IPv4 地址。使用 0.0.0.0 时，窗口中的 HTTP 地址仍显示本机回环地址；指定网卡时显示该 IP。外部电脑将 `127.0.0.1` 换为运行 AxisLab 电脑的局域网 IPv4，端口保持相同。示例：软件显示 `http://127.0.0.1:53120`，运行电脑 IP 为 `192.168.1.20`，另一台电脑使用 `http://192.168.1.20:53120`；Modbus 用 `192.168.1.20:1502`。

两台电脑需要互通，并允许对应 HTTP 和 Modbus 入站 TCP 端口。软件不自动修改防火墙。HTTP 桌面端口每次启动可能变化，请使用本次“连接信息”。当前协议无账号、TLS 或 Modbus 安全扩展，跨电脑能力用于可信教学局域网。

若 1502 被占用，可改 `AXISLAB_MODBUS_PORT=1503` 后重启。软件会显示实际端口；监听失败时 HTTP/场景仍可用，但“外部连接”明确报告 Modbus 错误。恢复仅本机连接：移除或设 `AXISLAB_LISTEN_ADDRESS=127.0.0.1` 后重启。已经运行的单实例不会应用新的环境变量，必须先关闭。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 连不上 | 核对两个端口、监听状态、本机/局域网 IP 和防火墙；不要把 HTTP 端口填成 Modbus 端口 |
| 标准异常 02 | 地址越界、写只读区，或心跳/提交未使用 FC16 原子双寄存器 |
| 标准异常 06 | 当前连接仍有活动任务或控制权，不能切换设备 |
| 错误 2 SessionChanged | 工程新建/导入/重开后重新选择设备、读取会话并使用新序号 |
| 错误 3 ConfigurationChanged | 尺寸、位姿、名称等配置改变；重新读取并确认配置版本 |
| 错误 11/12 | 控制权被占用/当前未持有；先申请控制权，保持心跳，或本地停止后重试 |
| 错误 14/15/16 | 关节越限、轴数或数值错误、速度错误；三轴只填三个目标，速度 1—100% |
| 错误 17 | 渲染器未连接；保持软件窗口打开并等待成像就绪 |
| 错误 40 ProgramActive | 积木程序运行或断点暂停期间持有工程控制权；先继续完成或停止程序，再直接控制机器人 |
| 动作途中停止 | 检查 TCP 断线、5 秒心跳、本地停止或取消；不得直接重放旧命令作为新动作 |
| HTTP 410 | 帧缓存淘汰或工程会话切换，重新拍照 |

完整运动、示教和积木编程已接入：Modbus 操作码 7/8/9 支持位姿 MoveJ、MoveL 和示教点；见《运动与示教接口.md》。视觉识别与标定求解将在阶段 7 实施。



## 运行积木程序

先在界面创建并保存程序，或导入 Samples/block-programming.scene.json。使用 Samples/ProgramClient 可经 HTTP 校验、运行、单步、继续和停止程序；完整命令见《积木编程使用说明.md》。程序由核心持有，客户端退出后可继续执行，需主动 stop；直接 Modbus 动作仍按原心跳规则。程序暂停期间外部不能抢占机器人。
