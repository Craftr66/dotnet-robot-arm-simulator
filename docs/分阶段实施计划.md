## 阶段 0：设计基线（本次）

已交付总体设计、需求规格修订和本计划。既有通信草案标记为案例参考，双相机传送带文档调整为示例模板。

## 阶段 1：空白场景与设备添加

实施：建立 C# 核心与三维界面原型、本地启动、健康检查、工程读写、设备注册和坐标树。设备库先提供基础几何体、参数化六轴占位模型、针孔相机图标/视锥。支持添加实例、选择、重命名、属性编辑与删除。

验收：从空白工程添加机器人与两相机；相机不依赖机器人存在；设备位置和 ID 保存重开一致；复制产生新 ID；非法挂载与引用环被拒绝。此阶段相机仅是可配置对象，界面不将其标为已经具备抓图能力。

验证 .NET/前端离线资源与三维依赖，记录测试机、依赖版本和许可证。OpenCV 绑定原型调整到阶段 7 开始时验证，当前不引入未使用的视觉原生依赖。

## 阶段 2：机器人基础运动

实施：确定六轴几何、轴向、零位与限位，建立核心 FK、关节状态、点动、简化关节运动与取消。建立法兰和 TCP 坐标节点，相机可挂法兰/工具并随机器人运动。

验收：六轴分别运动，连杆层级正确；已知构型下 FK 与独立计算一致；越限被拒绝；停止有效；挂载相机随动，独立相机不动。机器人以核心状态为准，不由界面私自改运动值。

## 阶段 3：相机拍照与传图（最早可单独使用的相机版本）

实施：CameraService、捕获 ID、场景快照、离屏渲染、ImageStore、PNG 预览/保存、HTTP 下载和最小 C# 控制台接收程序。先做针孔无畸变单次抓图，畸变和噪声后续加入。

验收：两台不同位姿相机拍出相应图像；移动相机/物体后下一帧更新；按固定 frameId 在界面、文件和 C# 获取一致 PNG；元数据含曝光时刻与位姿。运动中捕获绑定同一快照；渲染断开、捕获超时、缓存淘汰不返回旧图伪装成功。

完成后展示第一个小闭环：添加相机 → 拍照 → 外部 C# 收到图片，无需先实现标定或传送带。

## 阶段 4：通用 Modbus 与外部控制

实施：设备编号持久化、设备能力发现、公共头/设备窗口/命令提交、状态快照、控制权、心跳、取消与去重。冻结通用 Modbus v1 地址表、浮点编码、会话/帧令牌到 HTTP 资源的映射，并生成可读映射文件。

验收：独立 C# 程序选择机器人读状态和下发受限关节动作，选择任一相机经 Modbus 触发并通过 HTTP 下载对应帧；两个客户端不会串设备/串结果；删除或重开工程不把旧命令发给别的设备；断线、忙、重复提交和浮点字序测试通过。

此阶段 1—4 构成通用平台最小可用版本：场景可编辑、机器人可操作、相机可添加与传图、外部可通信。

## 阶段 5：完整运动与示教

实施：IK、MoveJ/MoveL、速度限制、路径采样、奇异与不可达处理、基本碰撞、TCP/工件坐标设置和示教点。运动接口在阶段 4 的统一命令模型上扩展。

验收：IK→FK 回代误差、直线轨迹、限位和碰撞检查有记录；至少五个示教点保存回放；改工具与设备参数后提示相关点位重新校验。暂不要求自动规划任意复杂障碍路径。

## 阶段 6：拖拽编程

实施：引入 Blockly，积木以稳定设备 ID 引用机器人/相机；编译为受控指令树，经现有调度器执行。支持变量、条件、循环、等待、运动、拍照、结果引用、单步、断点、停止与超时。

验收：拖拽建立“运动到点 → 选相机拍照 → 判断捕获成功 → 循环”的程序；运行中高亮；停止可取消等待；设备改名不失联，删除后明确提示缺失引用，不能按列表顺序绑定别的设备。

## 阶段 7：视觉与标定训练

2026-10-21 用户调整需求：视觉流程在 VisionMaster 中编写，WPF 通过 SDK 送入 AxisLab 图像、读取用户标定/定位结果，再通过 Modbus 控制仿真机器人。新的里程碑以[VisionMaster与WPF集成设计](VisionMaster与WPF集成设计.md)为准：7A 外部接入 → 7B 标定对象和采样 → 7C 固定相机定位 → 7D 完整手眼 → 7E 双相机/多坐标。下列原规划的标定能力目标保留，求解与业务编排职责按新文档调整。积木不再作为后续主线。

内部拆分：7A 图像检测及相机内参 → 7B TCP/参考系注册 → 7C 平面映射 → 7D Eye-in-Hand → 7E Eye-to-Hand 和工件坐标。

实施：棋盘格/标志/简单工件检测、采样向导、图像与机器人姿态配对、求解、依赖失效和报告。相机畸变与噪声模拟在本阶段加入并验证其与算法模型一致。

验收：从未标定工程开始由用户采样求解；隐藏真值不作算法输入；用未参与拟合的数据验证坐标转换，报告误差；退化姿态提示、参数改变失效、双相机结果隔离。按照需求规格中的初拟精度目标进行基准实验，未达到则分析修复后通过。

## 阶段 8：辅助设备与场景模板（按需增量）

内部拆分：8A 夹具与抓放确认 → 8B 传送带/光电/触发事件 → 8C 工位、标志和目标队列 → 8D 完整示例。

实施：作为可添加设备扩展设备库，不把这些对象自动塞进所有新工程。支持仿真硬触发事件链、联锁和场景业务积木。双相机传送带文档中的抓放流程在本阶段组合实现。

验收：用户可自行搭建或加载模板，完成从零标定、停带定位抓取和指定工位放置；积木及外部 C# 各能演示。测试三个工位、至少 20 个任务，覆盖满位、未知标志、重复触发、识别失败及夹持失败，无重复抓取或错误放置。连续运动跟踪抓取单独立项评估。

## 阶段 9：交付与回归

实施：离线资源和本地启动器/桌面包装、端口占用提示、工程版本兼容、日志导出、设备库说明、API/协议文档、C# 示例和分层课程。

验收：无开发环境的 Windows 测试机安装运行；添加设备、拍照传图、通信、示教、积木、标定及案例按教程复现。记录设备数量、图像分辨率、帧率、抓图时延、缓存峰值和已知限制，完成默认场景 30 分钟回归演示。
