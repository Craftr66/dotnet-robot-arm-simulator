# AxisLab Vision Demo 0.1 使用说明

这是新阶段 7A 的独立 WPF 联调程序。AxisLab 继续使用 0.6.0，虚拟相机经 HTTP 取图，WPF 通过真实 VisionMaster SDK 送入用户流程；机器人位姿运动通过 Modbus。它不需要 AxisLab 内的积木程序。

## 当前交付边界

已实现设备选择、固定帧 PNG 取图/校验、曝光机器人姿态配对、采样导出、VM .sol 加载、RGB24/MONO8 内存送图、自检、用户流程执行及输入输出映射、标定方案绑定、目标预检和单次 Modbus 定位。含停止、取消、心跳和错误提示。

需要你在 VisionMaster 中自行制作实际标定和识别方案。本次未制作你的 .sol，未验证其检测精度，也未完成标定板、九点采样向导、完整三维手眼或传送带抓放。SDK 送图和机器人运动分别通过真实集成测试；不将这两项测试称为已经跑通你的完整视觉算法。

## 环境与启动

本机已验证 VisionMaster 4.3.0（安装包内 SDK 指南标为 V4.3.1）、Windows x64、.NET Framework 4.8。Demo 使用本机的 VM SDK 和授权环境，不附带厂商 DLL 或算法包。其他版本需要核对接口和重新编译。

1. 打开 AxisLab，导入本 Demo 目录中的 Samples/vm-bridge.scene.json。场景含三轴、六轴、固定相机、末端相机和几何体；六轴与三轴间留有运动空间。它是接入练习场景，还不是标定板场景。
2. AxisLab 保持渲染窗口打开，在顶部“外部连接”复制实际 HTTP 地址。
3. 启动 AxisLab.VisionDemo.exe，填入该地址，点击“连接 / 刷新设备”。默认尝试读取 AxisLab 上次启动日志中的地址，仍需按实际地址核对。
4. 选择固定全景相机和机器人，点击“拍照”。右侧显示实际 PNG、帧号及曝光时的机器人 PoseId。
5. 修改样本保存目录，点击“保存当前配对样本”。每次生成固定 FrameId 命名的 PNG 和 observation.json。

程序目录需要完整保留。关闭 Demo 会取消其运动任务，断开私有 Modbus 连接；AxisLab 独立继续运行。

## 在 VisionMaster 中编写流程

### 先用本地图像调试

在 VM 中建立流程，添加“图像源”，先选择“本地图像”，加载 Demo 导出的 PNG。按你的目标添加定位、标定和映射模块。固定相机首个练习建议是 N 点平面映射；需要由你采集或示教真实对应的像素点和机器人坐标点，不能将像素直接当作 mm。

只有光学中心、标定平面、安装和目标高度假设一致时，平面标定结果才适用。N 点平面映射不代替完整三维手眼标定。

### 配置流程输入输出

这是项目约定的自定义流程接口，名称可以在 Demo 中改成你的名称。按 VM 流程的输入/输出配置建立：

| 方向 | 默认名称 | VM 类型 | 规则 |
| --- | --- | --- | --- |
| 输入 | AxisLabRequestId | 整数 | WPF 本次运行的请求编号 |
| 输出 | ResultRequestId | 整数 | 本帧处理结束后回传输入编号 |
| 输出 | CalibrationOk | 整数 | 1=你的 VM 流程确认当前标定可用；0=无效 |
| 输出 | TargetOk | 整数 | 1=本帧一个有效目标；0=无目标、失败或有歧义 |
| 输出 | RobotX | 浮点 | 机器人基坐标下目标 TCP 的 X，mm |
| 输出 | RobotY | 浮点 | 机器人基坐标下目标 TCP 的 Y，mm |
| 输出 | RobotRz | 浮点 | 机器人基坐标下目标 TCP 的 Rz，deg |

每个输出都须恰好一个值。每次流程开始重置有效标志，失败分支必须输出 NG；本帧计算完成后发布结果和 ResultRequestId。不要让失败分支保留上一次的成功标志或坐标。不要将 CalibrationOk 永久写成1来代替实际标定有效性判断。

RobotRz 应已包含角度方向、抓取方向和姿态偏置。相机像素角不一定等于机器人 Rz。首版 WPF 不隐式翻转角度或猜测坐标方向。

确认流程在 VM 内运行后保存 .sol。WPF 只加载这份方案，不保存或覆盖原方案。

## 集成与送图

1. 在 Demo 中选择 .sol，填写密码（如有）、流程名和图像源模块名。名称须完全匹配。
2. 点击“加载方案”。Demo 在内存中将指定图像源设为 SDK，原 .sol 文件不被修改。
3. 按流程选择 RGB24 或 MONO8。点击“图像源送图自检”，验证本次仿真图像确实进入 VM，并与图像源返回的像素逐字节哈希比对。自检只运行图像源，不生成定位目标。
4. 点击“将本帧送入 VM 并运行流程”。Demo 设置本次请求编号，运行流程并等待完成，再核对回传编号和读取结果。

VM 方案不满足约定时，送图自检仍可通过，正式定位会明确失败。输出缺失、多值、NG、请求编号不匹配和非有限数均不能生成可执行目标。

## 用视觉结果控制机器人

首版运动限定为固定相机、已知平面、单目标、机器人基坐标下的 MoveJ。

1. 先在 VM 完成有效标定并检测到目标，运行流程后应在右侧看到 RobotX/RobotY/RobotRz。
2. 输入你的“VM 标定方案标识”，点击“绑定当前设备与 VM 标定方案”。此操作记录设备和方案依赖，不是执行标定求解。绑定记录保存在样本目录。
3. 设置目标 TCP 的 Z、Rx、Ry 和速度。也可点击“读取当前 TCP 姿态”取得当前 Z/Rx/Ry。目标 Z 是 TCP 到位高度；修改它不能使原先的平面映射自动适用于不同物体高度。
4. 点击“预检 VM 目标”，AxisLab 检查 IK、限位和碰撞。
5. 点击“执行一次定位”。Demo 再次验证结果，申请机器人控制权，保持变化心跳，通过 Modbus 操作码7运行，完成后释放。SDK 提供 X/Y/Rz，WPF 不从仿真物体真实位置生成检测坐标。
6. 再次运动需要新的拍照和 VM 检测。顶部“停止机器人 / 取消任务”会取消本 Demo 的任务，并向当前所选机器人发送停止。

三轴自动仅约束位置；六轴使用完整目标姿态。末端相机目前可拍照和送 VM，首版不会把它当固定相机执行平面定位；需后续手眼及曝光姿态变换。

## 标定和结果失效

- 绑定关联当前 HTTP 地址、工程会话、相机/机器人 UUID 和配置版本、VM 方案 SHA-256、流程、图像源、像素格式和输入输出字段。
- 更换设备、重开工程、改安装/尺寸/TCP/工作坐标、修改方案或映射后需重新验证并绑定。
- 目标只在取图后30秒内使用；拍照后工程 revision 变化也需重新采集。预检与执行使用当前配置。
- 每次运行清除旧结果；停止和失败也清除可执行结果。Modbus 断开或变化心跳超过5秒中断，核心停止机器人。
- SDK 调用超过20秒被标为超时，不再产生动作；原生调用不能由 .NET 强制安全终止，需检查流程后重新打开 Demo。

## 样本格式

observation.json 保存图像文件名、FrameId、CaptureId、曝光时间、尺寸、SHA-256，以及所选机器人曝光时的关节、法兰/TCP 基坐标位姿和矩阵。单位 mm/deg，矩阵为列主序，T_A_B 将 B 坐标变换到 A。

样本不导出 cameraWorld 和 intrinsics，不把相机安装真值或真实内参交给标定算法。机器人运动中的帧可预览，但不能保存为本 Demo 的静态标定样本。

## 构建和代码

源码为 src/VisionDemo，不加入原有 AxisLab.slnx 默认构建，避免没有 VM 的电脑构建仿真核心时强制依赖厂商 SDK。发行包 Source 目录含 Demo 源码。

```powershell
dotnet build src/VisionDemo/AxisLab.VisionDemo.csproj -c Release -m:1 -nr:false
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/publish-vision-demo.ps1
```

其他安装目录可用构建参数 `-p:VmRoot="D:\VisionMaster4.3.0"`，运行前设置 `$env:AXISLAB_VM_ROOT='D:\VisionMaster4.3.0'`。默认目录是 C:\Program Files\VisionMaster4.3.0。

核心文件：AxisClient.cs 取图与配对；VisionService.cs 单 STA SDK 调用及像素转换；Models.cs 绑定和结果约束；RobotChannel.cs Modbus；MainWindow.xaml.cs 联调界面。后续计划见《VisionMaster与WPF集成设计.md》。
