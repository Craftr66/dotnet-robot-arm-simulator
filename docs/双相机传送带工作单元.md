# 示例场景：双相机传送带工作单元 v0.3

日期：2026-10-20。本文为通用平台上的一个示例模板，不规定平台必须使用双相机、传送带或固定工位数量。总体设计与通用接口以总体设计文档 v0.3 为准；本文中的 ID=1/2 仅为案例别名，实际使用工程设备 ID 与通信映射。当前为需求设计，功能尚未开发。

## 1. 场景组成

| 设备/对象 | 职责 | 可配置内容 |
| --- | --- | --- |
| 固定六轴机械臂 | 抓取、转运、放置、带末端相机观察工位 | 安装位置、机械参数、工具 TCP、速度、示教点 |
| 末端相机 CH，ID=2 | 识别工位标志、估计工位位置和方向 | 法兰安装、内参、手眼外参、曝光/触发参数 |
| 顶部相机 CT，ID=1 | 定位传送带上的待抓工件 | 固定安装、内参、相对基座外参、ROI |
| 传送带 V | 输送与暂存待抓工件 | 方向、速度、加减速、工作面高度、抓取区域 |
| 光电传感器 S | 检测来料并启动触发链 | 位置、检测范围、有效电平、边沿、去抖与触发延时 |
| 工位 Wi，默认 3 个 | 接收物品 | 工位 ID、布局、槽位、容量、放置规则 |
| 工位标志 Mi | 提供可识别 ID 与几何参考 | 标志字典、唯一 ID、实际尺寸、相对工位的安装变换 |
| 工件 O | 被识别和抓放的对象 | 类型、已知尺寸/高度、局部坐标、抓取偏置、目的工位 |
| 夹具 G | 抓放与确认 | 默认平行夹爪、开闭、抓取容差、夹持检测 |

末端相机和夹具同时刚性安装在法兰上，分别有独立外参；相机原点不能直接当作抓取 TCP。场景编辑器可显示识别区域、抓取区、工位槽位和碰撞体。

标志默认采用带唯一 ID 的 ArUco 标志/标志板，便于区分工位；其物理尺寸与角点定义需明确。可参考 [OpenCV 标志板位姿估计](https://docs.opencv.org/5.0/tutorials/objdetect/aruco_board_detection/aruco_board_detection.html)。这是建议默认值，后续可替换成其他可识别标志。

## 2. 用户要练习的标定

每个向导均提供“采集、查看数据、求解、独立验证、保存、清除”步骤。默认练习工程不提供可直接用于控制的安装真值。

| 标定任务 | 用户操作 | 产出及作用 |
| --- | --- | --- |
| 工具 TCP | 从不同末端姿态对准同一固定点，另行建立工具方向 | `T_F_G`，确定夹爪实际抓取参考；定点法本身只解位置，工具方向另行设置/示教 |
| 机器人基座注册 | 在已知参考系 W 中提供至少三个非共线参考点，示教对应 TCP 点并拟合，增加独立检查点 | `T_W_B`，将基座与场景/工作单元参考系关联；W 必须具有已知点坐标，不能只给三个无参考的点就求基座真值 |
| 传送带工作坐标 | 用 TCP 示教原点、沿输送方向点和面内第三点，检查非共线和正交化 | `T_B_V`，建立输送方向、平面和高度基准 |
| 两台相机内参 | 分别从多视角采集已知格尺寸的标定板 | `K_CT,D_CT` 和 `K_CH,D_CH` |
| 末端相机手眼 | 标定板固定，移动末端多姿态同步采集图像与法兰位姿 | `T_F_CH`，建立随动相机与法兰关系 |
| 顶部相机手眼 | 标定板刚性装在末端，顶部相机固定，多姿态采集并按 Eye-to-Hand 正确转换输入 | `T_B_CT`，把顶部相机观测转换到机器人基座 |
| 工位坐标 | 先示教工位原点及轴向，再确定标志安装关系；也可导入已知安装尺寸并独立验证 | 每个工位的 `T_Mi_Wi` 与放置槽位；运行时识别标志更新 `T_B_Wi` |
| 工件/抓取坐标 | 定义工件局部原点和轴向，在样件上示教夹持位置与姿态 | `T_O_Gpick`，把被识别工件位姿变成 TCP 抓取位姿 |
| 工位放置关系 | 在工位局部坐标中示教槽位、工件落位姿态和撤离方向 | `T_Wi_Oplace`，配合夹具持物关系生成放置 TCP 位姿 |

“标定机械臂坐标”在首版指 TCP、工作坐标及基座注册。机器人关节零偏、连杆长度等运动学参数辨识是另一类标定，暂不包含。仅在机器人自身基坐标中做任务时，不必额外求 `T_W_B`；需要与场景外部参考系关联时才使用它。

手眼算法输入输出方向依照所选 API 转换，不能把同一输入直接用于两种安装模式。参考 [OpenCV 手眼标定文档](https://docs.opencv.org/4.12.0/d9/d0c/group__calib3d.html)。

## 3. 坐标如何串起来

统一记法：`T_A_B` 把 B 系坐标变到 A 系。B=机器人基座，F=法兰，G=抓取 TCP，CT=顶部相机，CH=末端相机，Mi=第 i 个标志，Wi=第 i 个工位，O=工件。

### 顶部相机给出抓取位置

```text
图像角点/轮廓 + 相机内参 + 已标定的平面/已知工件几何
    → 工件在顶部相机中的位姿 T_CT_O
    → T_B_O = T_B_CT · T_CT_O
    → T_B_Gpick = T_B_O · T_O_Gpick
```

对于平面目标也可直接把去畸变像素射线与已知工作平面求交到基坐标，结果应与上面的坐标链一致。已知工件高度时使用对应目标面，不能默认所有可见表面都在传送带面上。无高度约束或已知几何时，单目中心点不能给出任意三维位姿。

### 末端相机给出工位位置

```text
曝光时的机器人法兰位姿 T_B_F + 已标定的末端相机安装 T_F_CH
    + 图像识别标志位姿 T_CH_Mi + 标志到工位关系 T_Mi_Wi
    → T_B_Wi = T_B_F · T_F_CH · T_CH_Mi · T_Mi_Wi
```

标志 ID 负责确定工位身份，角点与已知尺寸负责估计位姿。选择可见、质量达标且朝向合理的解，平面位姿歧义/质量不足时拒绝更新。标志本身不能提供未知的标志到槽位安装偏置，也不能证明工位空闲。

### 把工件放入工位

```text
目标工件落位：T_B_Oplace = T_B_Wi · T_Wi_Oplace
刚性持物关系：T_G_O（抓取确认时确定并校验）
放置 TCP：T_B_Gplace = T_B_Oplace · inverse(T_G_O)
```

首版逻辑夹持以已知夹持关系建模；若抓取偏差超出容差则报失败，不能瞬间吸附远处工件掩盖标定错误。夹持偏移不能默认恒为零。

抓放目标位姿对应 TCP，送入逆解前需根据 `T_F_G` 转换为法兰目标；界面和 C# 接口应明确是否接收 TCP，避免重复应用工具偏置。

## 4. 光电与硬触发仿真

仿真核心建立事件链，模拟硬件触发行为；不宣称桌面软件提供真实电气触发或硬实时响应。光电边沿、曝光开始、曝光完成和图像处理完成分别记录。

支持两种触发配置：

1. **首版默认：停带定位链。** 光电有效边沿建立 triggerId/来料记录并发起停带；传送带到位静止后，由触发联锁向顶部相机发一次曝光事件。传感器、停止距离及相机视野布局必须使目标停在视野和可抓区内。
2. **直接边沿曝光。** 光电边沿直接触发相机，可配置延迟、忙时丢帧/排队策略；如果曝光后继续输送，结果带曝光时刻的位置。停带抓取须在停止后重拍；连续跟踪版本则使用带位移和时间补偿。

两种配置都由核心事件调度执行，Modbus/C# 只读取计数、配置模式或下发启停，不能通过低频轮询替代仿真硬触发。第一种是停带联锁后的触发，不能在界面误标成“光电边沿立即曝光”。

记录 cameraId、triggerId、frameId、曝光仿真时刻、法兰快照、带位移、目标关联及标定版本。渲染延迟不改变已冻结曝光场景。光电事件只用来触发，不得把仿真物体隐藏坐标直接当作视觉检测结果；目标身份可用标志/跟踪关联或首版单件在场规则确定。

触发去抖、防同一遮挡重复触发、相机忙状态、事件队列上限和漏拍计数可见。暂停时所有设备使用同一仿真时钟冻结；恢复后不得重复生成边沿。

## 5. 默认完整任务

1. 加载“未标定工作单元”，用户完成并验证相关标定，示教观察点、过渡点与抓放接近点。
2. 配置“工件类型/任务 → 目的工位”规则；检查夹具、工位容量、视野与抓取区域。
3. 启动传送带；光电检测来料，停带并等待稳定。
4. 顶部相机曝光，识别工件，生成含帧号和标定版本的目标；检查坐标和可达性。
5. 预留目标和目的槽位；移动至预抓取点、接近、夹持、确认、抬升。
6. 经示教过渡点移至对应工位观察点；末端相机识别预期工位标志，更新工位坐标。
7. 校验工位 ID、标志质量、空位与新鲜度；计算放置 TCP，接近、放置、释放确认、撤离。
8. 完成目标、更新工位占用，满足放行条件后恢复输送；记录整条任务链。

观察路径应考虑夹持物遮挡末端相机，不能只在空手状态验证可见性。工位允许手动复位/清空以便循环练习；工位移动后由重识别更新其位置，标志相对工位的安装变化则必须重新标定该关系。

先采用保守的单件在场、一次一抓流程；多目标用有界候选队列扩展。目标状态为 Detected → Reserved → Picked → Placed，失败/过期转 Failed/Expired。视觉重拍通过关联更新同一候选，不能重复建立抓取任务；夹持确认后不得再次抓该目标。

## 6. 积木与外部控制

积木可组合：等待光电、启停传送带、等待静止、选择相机、拍照、识别工位、读取目标、转换坐标、检查标定、预留槽位、MoveJ/MoveL、夹爪开闭、等待抓放确认、记录结果。

支持两种明确的控制方式：

- 本地积木编排：C# 发启动/停止任务并监视状态，本地流程管理抓放。
- 外部 C# 编排：C# 持有控制权，调用运动、视觉及设备命令并维护任务；核心仍强制校验目标、标定和联锁。使用接口需携带目标和工位上下文，不允许用过期结果启动任务。

两种方式互斥，采用相同运动与设备服务。传感器触发/相机采集作为异步设备事件持续受调度，不因运动命令 Busy 而静默丢失；不能借异步事件绕过运动控制权。

Modbus 增加双相机结果窗口、输送状态、光电事件、工位和目标状态，详见通信协议 v0.2 草案。图片和完整队列详情使用本地界面/HTTP，Modbus 暴露当前候选和必要索引。

## 7. 异常与验收

| 情况 | 预期行为 |
| --- | --- |
| 未标定、相机安装或工具改变 | 指出失效关系并阻止受影响动作 |
| 光电重复边沿、相机忙或漏拍 | 计数可见、任务去重；队列满停带并提示 |
| 工件离开 ROI/可抓区、结果过期 | 不抓取；按配置重拍、停带等待或报错 |
| 工位未知、标志遮挡、姿态歧义 | 保持持物状态，停止放置流程并提示恢复步骤 |
| 工位满、目标工位不匹配 | 拒绝放置；按显式规则选择备选，禁止静默改工位 |
| 夹持未确认、释放未确认 | 不推进到成功状态，禁止更新错误占用 |
| 不可达、碰撞、断线、停止 | 按调度规则停止；已夹持物不自动松开，带停止，恢复后核对任务 |

验收以三工位、两相机、至少 20 个任务为初始演示集。用户从未标定状态开始，完成坐标建立和标定；混合工件位置、旋转角和目的工位，核对抓取/放置误差与任务日志。移动一个工位后重新识别，放置目标应随工位变化；改变标志安装偏置则应提示重新校准。

连续运动抓取放到后续扩展：增加编码器/虚拟编码器、带位移同步、目标速度/位置更新、预测拦截、跟随运动和抓取窗口验证。先完成本文件的停带基线，再单独确定其性能指标与开发工作量。
