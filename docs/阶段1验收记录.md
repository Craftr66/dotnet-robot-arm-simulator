# 阶段 1：场景与设备编辑器 v0.1

日期：2026-10-20。结论：阶段 1 的场景编辑闭环已实现，下一阶段是六轴基础运动。OpenCV 依赖验证移至视觉阶段，未声称已验证视觉能力。

## 实现内容

- Windows 本地 ASP.NET Core 服务，同源提供三维界面和 JSON API；无需 CDN。
- 空白场景、轨道视角、网格、坐标轴、选中框、平移/旋转操纵器及聚焦。
- 设备库：通用六轴静态模型、针孔相机、长方体，最多 128 个场景对象。
- 添加、重命名、复制、隐藏、删除、坐标编辑、相机内参/分辨率及几何尺寸编辑。
- 相机可独立存在；所有对象可挂载至父对象基坐标，后台检查父对象存在性和循环。
- UUID 稳定，设备编号递增且删除后不复用；复制生成新身份。
- 父对象删除确认显示子对象数量，支持确认级联或取消；当前没有保留世界位姿解挂按钮。
- 本地 JSON 工程保存/列表/打开、浏览器导入导出、工程版本及参数校验。
- 原子临时写入后替换、2 MiB 工程大小限制、修改版本冲突检查和错误事件日志。

本机 Windows 10 x64，.NET SDK 10.0.401，.NET/ASP.NET 运行时 10.0.12，Node.js 24.19.0，pnpm 11.25.0。使用已安装的 Edge 完成浏览器验收；测试机 CPU/GPU 与真实硬件帧率基线尚未测量，不以本次软件渲染帧率作为性能验收结论。

参考：[Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)、[ASP.NET Core 静态文件](https://learn.microsoft.com/en-ie/aspnet/core/fundamentals/static-files?view=aspnetcore-10.0)。

## 当前 HTTP 接口

| 方法与路径 | 实际用途 |
| --- | --- |
| GET `/api/health` | 版本与当前阶段 |
| GET `/api/v1/device-types` | 设备类型及已实现能力 |
| GET `/api/v1/project` | 工作区快照、会话、修改版本和保存状态 |
| GET `/api/v1/devices` | 当前设备实例 |
| GET `/api/v1/projects` | 已保存工程列表 |
| POST `/api/v1/project/new` | 新建，传 expectedRevision/name |
| POST `/api/v1/project/save` | 保存，传 expectedRevision/name |
| POST `/api/v1/project/open` | 打开，传 expectedRevision/fileId |
| POST `/api/v1/project/import` | 导入，传 expectedRevision/project |
| POST `/api/v1/devices` | 添加，传 expectedRevision/typeId |
| PUT `/api/v1/devices/{id}` | 更新，传 expectedRevision/device |
| POST `/api/v1/devices/{id}/duplicate` | 复制，传 expectedRevision |
| DELETE `/api/v1/devices/{id}` | 删除，查询参数 expectedRevision/cascade |

所有修改需带最新工作区 revision；冲突返回 409。无效参数通常返回 422，缺少设备返回 404。此版本没有 WebSocket 状态推送，界面通过命令响应更新；健康检查每 10 s 一次，其他页面修改会在下一次写入时触发冲突检查。

## 限制与下一步

机械臂是参数化静态示意模型，没有关节操作、FK/IK、插补或碰撞；相机只有安装与内参配置和视锥，没有拍照或图像传输；Modbus、C# 客户端样例、积木、识别、标定、输送与工位业务均待后续阶段。

挂载相对父对象基坐标；法兰/工具挂载、保留世界位姿重新挂载以及撤销/重做待增加。启动默认是空白工作区，用户通过“打开”加载已有工程。当前工程由 C# 服务保存为一个 JSON 文件，未来加入图片/程序/标定时扩展为工程目录，不影响现有 ID。

下一步：保持现有工程格式兼容，添加机器人六轴参数、关节状态和命令校验，建立 FK 与法兰坐标，再加入相机随动验证。
