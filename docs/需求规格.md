# 项目需求规格 v0.3

2026-10-21 需求更新：用户选择通过 WPF＋VisionMaster SDK 使用 AxisLab 虚拟相机，在 VM 中编写标定/识别流程，再由 WPF 控制仿真机器人。后续视觉开发以[新的集成设计](VisionMaster与WPF集成设计.md)为准，内置积木不再作为主要编程方式。

定位修订：本项目为可添加机械臂、相机及场景对象的通用仿真平台。总体架构与当前开发顺序以[总体设计文档](总体设计文档.md)和[分阶段实施计划](分阶段实施计划.md)为准。本文保留传送带案例的详细需求，但案例不是平台默认布局或必选设备。

编制日期：2026-10-20。本文为开发基线，未指定的硬件型号、性能指标和技术选型均为建议默认值。

## 1. 产品目标

制作一套 Windows 本地运行的教学仿真软件，使用户无需真实机械臂和工业相机即可完成：

1. 操作六轴机械臂，理解关节、TCP、基坐标和工具坐标。
2. 使用积木拖拽编程完成运动、拍照、识别、逻辑判断及 IO 联动。
3. 配置虚拟相机，练习相机内参、平面映射和手眼标定。
4. 完成示教点录制、轨迹回放和视觉定位演示。
5. 使用独立 C# 程序经 Modbus TCP 读状态、发运动指令、触发拍照和读取结果。

平台最小端到端目标：创建空白工程 → 添加机械臂与相机 → 配置安装位置 → 操作关节 → 拍照并预览/保存 → 外部 C# 获取同一帧图像 → Modbus 读取设备状态并控制设备。

后续示例：用户完成标定 → 光电检测来料 → 相机定位 → 抓取 → 识别工位 → 放置。详见[双相机传送带工作单元](双相机传送带工作单元.md)。

## 3. 功能需求

### 3.0 通用场景与设备管理

- 从空白工程添加、复制、删除、重命名设备与场景对象；相机可独立存在，不要求先添加机械臂。
- 设备库首批包含通用六轴机械臂、单目相机和基础几何体；后续添加夹具、标定板、传送带、传感器、标志及工位。
- 每个实例具有稳定 ID、类型、属性、父节点、局部变换、状态与能力列表，不依靠名称或添加顺序寻址。
- 可选择相机挂载对象并配置外参，删除父设备时显示引用影响；运行中禁止破坏正在使用的设备拓扑。
- 相机支持软件拍照、帧预览、PNG 保存及 C# 图像下载，不以先实现识别算法为前提。
- 项目文件保存设备、挂载、程序、标定和通信映射；加载校验版本、资源、引用及单位。

### 3.1 场景与机械臂

- 三维场景提供旋转、缩放、平移、复位视角；显示地面、工作台、标定板和工件。
- 机械臂运行时基座固定，编辑时可设置安装位置；可按需编辑工位、标志、传送带、传感器及相机布局，并验证可达性与视野。练习模式移动设备后不得自动同步用户标定值。
- 六个关节具有独立轴向、零位、上下限及速度限制，模型尺寸使用真实单位。
- 关节滑块与按钮点动，显示关节角、末端位姿及运动状态。
- 正运动学计算 TCP；逆运动学支持目标位姿、初始关节种子和失败原因。
- 支持 MoveJ 关节插补、MoveL 笛卡尔直线插补；执行前检查路径采样点可达性及关节限位。
- 多解选择优先靠近当前姿态；奇异附近降低速度或明确拒绝，不能静默跳变。
- 可视化基坐标、法兰、工具、工件、相机、标定板坐标系；支持工具 TCP 和工件坐标设置。
- 显示 TCP 轨迹；提供仿真停止、暂停、继续、复位与速度倍率。
- 首版支持基本连杆/工作台碰撞检测与自碰撞检查，允许用简化包围体；适用范围在界面说明。

### 3.2 示教与回放

- 保存、重命名、修改、删除示教点；记录关节角、TCP 位姿、工具与工件坐标引用。
- 点动至目标后记录点位，生成 MoveJ/MoveL 积木。
- 按点位顺序回放，显示当前步骤；支持单步与断点。
- 修改工具或机器人参数后，对受影响点位提示重新校验。
- 提供回零、绕行、定点拍照、平面目标定位和拾放演示工程。

### 3.3 拖拽编程

| 积木分组 | 代表指令 |
| --- | --- |
| 流程 | 开始、顺序、条件、循环、等待、变量、子程序 |
| 机械臂 | MoveJ、MoveL、读取位置、设置速度、夹爪开合、移动到示教点 |
| 相机 | 选择相机、设置参数、触发拍照、等待图像 |
| 视觉 | 设置 ROI、查找标定板、检测目标、读取结果、像素转平面坐标 |
| 标定 | 记录图像与机器人姿态、求解标定、加载标定、坐标转换 |
| 通信/IO | 读取输入、设置输出、等待寄存器条件、发布视觉结果 |
| 输送与工位 | 启停传送带、等待光电边沿、选择相机、识别工位 ID、检查空位、预留目标、抓取确认、放置确认 |

- 积木编译为受控指令树，由统一运行时解释执行；保存工程同时保存积木工作区与指令版本。
- 运行前检查缺失参数、未定义点位、缺失标定、非法数据连接和循环边界。
- 执行时高亮当前积木，显示变量、输入输出、错误和时间戳日志。
- 所有等待均可取消并具有超时；循环可被停止，避免界面或设备执行线程阻塞。
- 视觉流程支持参数拖拽配置和结果引用；初期与主流程共用编辑器，独立节点式视觉编辑器后续评估。

### 3.4 虚拟相机与识别

- 相机可放置于场景或挂载于末端；提供位置、方向、分辨率和内参设置。
- 提供相机画面、视锥、ROI、角点、目标坐标及置信/质量信息叠加显示。
- 图像必须由当前三维场景渲染产生；加入针孔模型与可选畸变、噪声，确保图像和相机参数一致。
- 触发时冻结对应场景状态，图像、机器人位姿、帧号和时间戳形成同一采样记录。
- 支持棋盘格角点提取，以及简单圆形、矩形目标的中心与平面角度检测。
- 目标离开视野、遮挡、角点不足、曝光模拟不佳或结果过期时返回明确失败状态。
- 图片与标定数据可导出；图像通过本地文件/HTTP 获取，Modbus 传输索引与数值结果。
- 两台相机独立保留 cameraId、内参、安装外参、帧号和结果；顶部相机负责来料定位，末端相机负责工位标志识别。已知尺寸标志可用于工位位姿估计，具体定义见工作单元文档。

### 3.5 标定训练

必须区分三种任务，不能把平面映射当成完整手眼标定。

1. **相机内参标定**：从多视角棋盘格图像估计焦距、主点和畸变，展示重投影误差与逐帧误差。
2. **固定工作平面标定**：由像素映射到已知工作平面；只有平面和姿态假设成立时才能用于定位，不能由单个像素恢复任意三维点。
3. **完整手眼标定**：
   - Eye-in-Hand：相机刚性固定在法兰/工具，标定板固定在工作区，求解相机相对末端的外参。
   - Eye-to-Hand：相机固定在工作区，标定板刚性固定在末端，求解相机相对基座的外参；明确变换方向与输入转换。

训练流程：选择安装模式 → 设置板格尺寸 → 规划多样化姿态 → 到位静止后同步采集 → 检测角点 → 过滤无效样本 → 求解 → 独立验证 → 保存标定。

- 建议采集 15—25 组姿态，检查旋转方向、角度跨度和覆盖范围；不能仅凭样本数量判定有效。
- 展示内外参矩阵、有效样本数、重投影误差、退化提示、独立目标定位误差。
- 仿真隐藏真值仅用于生成图像和评估，不得作为算法输入冒充标定结果。
- 教学模式允许对照真值解释误差，练习模式隐藏真值。
- 相机分辨率、内参、安装变换、标定板尺寸、TCP 或相关机器人参数变化时，按依赖关系使标定失效。
- 用户需分别完成 TCP 标定、机器人基座相对工作单元参考系的注册、传送带工作平面、双相机内参和手眼、各工位/工件坐标及抓放偏置。坐标注册不等同于机器人连杆参数辨识；详细操作与变换链见工作单元文档。

### 3.6 Modbus 与 C#

- 早期即建立 Modbus 服务和 C# 冒烟示例，随后逐步增加运动、视觉、程序控制。
- 支持连接配置、状态读取、IO、指令下发、错误码、结果读取、心跳和断线处理。
- 将命令接受、运行、完成、失败分开；支持序号和重复命令去重。
- 界面示教、积木程序和外部客户端通过同一调度器执行；运动控制权互斥，状态允许多方读取。
- 外部运动控制断线/心跳超时后停止接收新动作，并按约定减速停止；本地程序仅在不依赖外部控制时独立继续。
- C# 示例提供连接、读状态、MoveJ、视觉触发、读取坐标、等待完成、超时与错误处理。
- 增加相机选择、光电事件计数、传送带控制、目标 ID、工位 ID、占用状态与抓放结果。传感器到相机的仿真硬触发在核心事件链内执行，不依赖 C# 轮询捕捉边沿。
- Modbus RTU、仿真软件主动作为客户端访问外部 PLC 为后续扩展项。

### 3.7 工程与教学资料

- 本地工程保存机器人参数、场景、示教点、程序、相机参数、标定及版本号。
- 工程重新打开后恢复配置；不自动恢复正在执行的动作或外部控制权。
- 支持日志导出、示例一键加载、协议地址查看和常见错误说明。
- 导出的标定文件包含坐标方向、单位、输入数据摘要、质量指标和依赖参数版本。

### 3.8 示例扩展：输送、抓取与工位管理

- 传送带有方向、速度、启停、减速与停止状态；工件具有唯一任务 ID、类型、尺寸和目标工位规则。
- 光电传感器模拟遮挡、上升/下降沿、去抖、触发延迟；记录事件时刻与实际曝光时刻。
- 默认停带稳定后触发定位帧；若演示光电边沿直接曝光，停止后必须重拍或按位移补偿，禁止使用移动前的旧坐标抓取。
- 工位维护唯一标志 ID、标志到工位变换、槽位、占用、预留及放置偏置；标志识别不直接等同于空位检测。
- 抓取包含预抓取、接近、夹持确认、抬升；放置包含识别确认、预放置、下降、释放确认及撤离。失败不得记为成功。
- 首版以已知平面和已知高度工件演示；多目标建立有界队列、去重与超时，队列满时停带，不覆盖未处理目标。
- 校验后展示计算坐标、预期轨迹和使用的标定版本，用户可单步执行并观察标定误差。

## 4. 建议架构

采用本地服务加浏览器界面；最终可增加桌面外壳。下表为建议选型，阶段 1 通过依赖与原型验证后锁定版本。

| 层 | 建议实现 | 职责 |
| --- | --- | --- |
| 界面与三维 | TypeScript、Three.js、Blockly | 三维场景、交互、积木、虚拟图像渲染 |
| 本地核心服务 | C#、受支持的 .NET LTS、ASP.NET Core | 工程、运动学、调度、状态、Modbus TCP |
| 视觉计算 | C# 调用 OpenCV 的兼容绑定，原型阶段验证覆盖 | 角点、内参、位姿、手眼求解 |
| 内部连接 | HTTP 与 WebSocket | 图像上传、配置、命令、状态订阅；共同访问核心调度器 |
| 对外连接 | Modbus TCP | 外部 PLC/C# 的控制与结果交换 |
| 交付 | 本地启动器，后期可加 WebView2 外壳 | 启动服务、检查端口、加载界面、关闭清理 |

浏览器不能直接承担 TCP 监听，因此 Modbus 服务由本地核心进程提供。机器人位姿以核心服务为准，界面插值只负责显示；相机捕获时绑定核心状态快照并确认渲染完成。前端离线/捕获失败时相机指令应失败，不能返回上一帧成功。

选择上述结构是为了复用 C# 核心与后续客户端示例，同时兼顾三维与积木编辑器。若后续明确要求 Unity 或特定机器人 SDK，应先复核架构。

## 5. 数据与坐标约定

- 界面、工程与协议：长度 mm、角度 deg；视觉算法与渲染适配层显式转换单位，禁止隐式混用。
- 机器人右手坐标；相机坐标为 X 向右、Y 向下、Z 向前；渲染坐标通过显式变换适配。
- 记号 `T_A_B` 表示将 B 系坐标变换到 A 系：`p_A = T_A_B · p_B`。
- 内部旋转使用旋转矩阵或归一化四元数。姿态显示约定 `R = Rz(rz) · Ry(ry) · Rx(rx)`，并处理欧拉角不唯一情况。
- 工具 TCP 与法兰坐标分别保存；手眼求解使用哪个末端坐标必须写入数据元信息。
- 所有采样保存 frameId、poseId、captureTimestamp 和参数版本，避免图像/姿态错配。
- 多设备事件额外保存 cameraId、triggerId、targetId、stationId 和仿真时钟；暂停时一致冻结时间，避免工件继续移动而运动/视觉停止。
- 命令状态建议为 Idle、Accepted、Running、Completed、Faulted、Cancelled；相机结果另有 Valid 与 frameId。

## 6. 质量与整体验收

性能为初始目标：单机械臂基础场景在约定测试机上三维显示不低于 30 FPS；局域网/本机状态轮询默认 100 ms。记录相机分辨率和数量，先验收单次抓图，不承诺多相机无限帧率。阶段 1 记录测试机 CPU/GPU、分辨率和模型规模，后续据此验收，不承诺硬实时。

| 场景 | 验收结果 |
| --- | --- |
| 通用平台最小闭环 | 空白工程添加设备、修改属性、保存重开、按相机 ID 抓图并由 C# 下载同一帧 |
| 手动示教 | 六关节点动、限位提示、保存至少 5 个点并回放 |
| 拖拽程序 | 组合运动、拍照、判断、循环；单步、暂停和停止可用 |
| 平面视觉定位 | 随机移动平面目标，使用图像检测与标定映射完成 TCP 定位 |
| 内参及手眼 | 两种安装模式分别从图像和姿态求解，使用未参与拟合的数据验证 |
| 双相机工位抓放 | 用户从未标定工程开始，独立标定后完成来料触发、停带定位、抓取、识别工位及放置 |
| 工位与目标异常 | 未知标志、工位满、重复触发、漏检、夹持失败、旧帧及标定过期不得导致错误放置 |
| 外部控制 | 独立 C# 程序读状态、下发动作、触发拍照、读取带帧号的结果并等待完成 |
| 异常恢复 | 覆盖不可达、越限、识别失败、超时、重复命令、控制权冲突与断线 |
| 工程交付 | 新机器安装运行，保存/重开工程，按教程复现完整流程 |

理想无噪声回归场景初拟：内参重投影 RMS ≤ 0.5 px，独立平面定位误差 ≤ 1 mm，手眼外参平移误差 ≤ 1 mm、旋转误差 ≤ 0.5°。这些是待基准实验验证的工程目标；还需报告验证点数量、空间覆盖、最大值及均方根，带噪声工况单独建立基线。

## 7. 后续确认项与默认处理

当前无需这些信息即可开始骨架开发：未指定机器人品牌时使用通用 6R；相机为可添加的单目设备；未指定串口时使用 TCP；未指定客户端界面时先做 C# 控制台示例。空白工程不自动生成传送带和工位；案例模板采用 3 个工位、ArUco 标志、平行夹爪、已知高度工件及停带抓取，均可修改。

后续需明确：是否有目标品牌与尺寸、最终是否必须为独立桌面窗口、是否需要 RTU/串口、是否需要真实设备接入、验收电脑配置。若范围扩大，调整相应阶段工作量。
