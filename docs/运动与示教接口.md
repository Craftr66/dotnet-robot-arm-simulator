# AxisLab 0.6.0 运动与示教接口

日期：2026-10-21。HTTP 前缀 `/api/v1`，Content-Type 为 `application/json`。通过 `GET /project` 取得 sessionId、revision、机器人 ID、示教点及 teaching 失效标记。运动、点位写入使用最新 expectedRevision，冲突返回 409 RevisionConflict。

## HTTP

| 方法与路径 | 用途 |
| --- | --- |
| GET /project | 工程和 runtime；project.teachPoints 为持久点位，teaching 包含 point/stale/reason |
| GET /runtime | 实时关节、TCP、工件坐标、命令 ID、进度、步骤、错误 |
| POST /robots/{id}/joints | 既有关节 MoveJ；joints、speedPercent、expectedRevision |
| POST /robots/{id}/preview | 求解并预检笛卡尔目标，不运动、不修改 revision |
| POST /robots/{id}/cartesian | 提交位姿 MoveJ 或 MoveL |
| POST /robots/{id}/stop | 停止所选机器人并撤销控制权，无须 expectedRevision |
| POST /robots/{id}/teach-points | 记录当前点；name、frame、expectedRevision |
| PUT /teach-points/{pointId} | name、action、expectedRevision；action 为 rename/update/revalidate/delete |
| POST /robots/{id}/play | 按 pointIds 数组顺序运行；kind、speedPercent、expectedRevision |
| PUT /devices/{id} | 在 device.robot.toolTransform/workTransform 配置工具与工件坐标 |

预检 body 直接传运动对象：

```json
{
  "target": { "x": 420, "y": 130, "z": 410, "rx": 168, "ry": 60, "rz": -173 },
  "frame": "base",
  "kind": "MoveL",
  "speedPercent": 25,
  "positionOnly": false
}
```

`frame` 为 base/world/work，`kind` 为 MoveJ/MoveL。三轴固定按仅位置求解。成功返回 `{joints,duration,kind,samples,nearSingularity,warning}`，duration 单位秒；只有通过 IK、限位、路径误差和碰撞预检才返回成功。

执行 body 使用相同运动对象放在 motion 中：

```json
{
  "expectedRevision": 12,
  "motion": {
    "target": { "x": 420, "y": 130, "z": 410, "rx": 168, "ry": 60, "rz": -173 },
    "frame": "base", "kind": "MoveL", "speedPercent": 25, "positionOnly": false
  }
}
```

成功返回 WorkspaceSnapshot，仅代表规划通过并启动。轮询 `/runtime`，通过 commandId 匹配本次命令；status 为 Running/Completed/Cancelled/Failed。读 motionErrorCode、motionMessage 查看运行中断原因，stepIndex 为 1 起步数、stepCount 为总步数，activeTeachPointId 表示当前点。

示教点记录示例 `{ "expectedRevision": 13, "name": "P1", "frame": "work" }`。回放示例 `{ "expectedRevision": 14, "pointIds": ["点一GUID","点二GUID"], "kind": "MoveJ", "speedPercent": 25 }`。整组预检通过后才启动，逐点停稳；数组可表达自定义顺序，1—256 个步骤。点位失效时返回 409 StaleTeachPoint。

运动中禁止设备与点位编辑/保存。HTTP 本地控制不能抢占 Modbus 控制权；本地 stop 可以撤销外部控制。示教点编号在全工程唯一并单调分配，删除不复用。

## Modbus v1 扩展级别 1

基本连接、会话、所有权、心跳、序号去重和图像映射沿用《ModbusTCP操作协议v1.md》。协议寄存器 1 仍为 1，寄存器 2 为 6；新增寄存器 123=1 表示支持本扩展。旧操作码地址及含义保留，能力位不能按等值比较，应按位检测。

| 地址 | 含义 |
| --- | --- |
| 17 / 发现行能力 | 机器人增加 bit7 位姿 MoveJ、bit8 MoveL、bit9 示教点；合计 0x039F |
| 96 | 运动状态补充 4=Failed |
| 119、120 | 当前步骤、总步骤，UInt16；非机器人为 0 |
| 121 | 0 无路径、1 MoveJ、2 MoveL |
| 122 | 当前运动错误码 |
| 123 | 扩展级别 1，所有设备通用 |
| 124—127 | 保留零 |

新操作码：

| 202 操作码 | 名称 | 参数 |
| --- | --- | --- |
| 7 | 目标位姿 MoveJ | 204=机器人轴数；206—217 为 X/Y/Z/Rx/Ry/Rz 六个 Float32；218—219 速度 |
| 8 | MoveL | 参数同 7 |
| 9 | 运行一个示教点（MoveJ） | 226=点编号 UInt16；218—219 速度；目标区可置零 |

7/8 的 203 标志：bit0=仅位置；bits1—2=坐标系（0 base，1 world，2 work），合法值 0—5。三轴自动按位置求解。其他操作码 203 仍须零。205、227—229 总须零；226 只在操作码 9 使用。操作码 3 保持原来的 3/6 轴关节目标，未使用轴必须零。220—223 预期会话、224—225 预期配置和 232—233 最后提交序号的规则不变。

7/8/9 都要求当前连接持有机器人控制权；成功启动后命令状态为 2，完成为 3。预检失败为 6 Rejected，机器人不移动；运行中碰撞为 4 Failed。单段规划可能需要数秒，自编客户端建议运动提交请求超时至少 10 s，其他查询维持短超时；运动期间每秒更新变化的 UInt32 心跳，避免 5 s 失权。

新增错误：30 IkUnreachable，31 CollisionDetected，32 SingularPath，33 PlanningLimit，34 StaleTeachPoint，35 TeachPointNotFound，36 InvalidPose，37 InvalidFrame，38 UnsupportedPose，39 MountedRobotUnsupported；未分类仍为 255。HTTP 返回可读 code/message，Modbus 历史 `/communication/clients/{clientId}/commands/{sequence}` 同样提供可读原因。

完整机器映射可从 `/communication/map` 获取，或在软件顶部“外部连接”导出。示教点的创建、修改和批量顺序回放通过 HTTP/界面完成，Modbus 9 用于执行已存在点。
