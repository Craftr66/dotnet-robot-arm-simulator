> 文档状态：未实现、未冻结的“传送带工作单元示例映射”。v0.3 已调整为通用平台；下面固定顶部/末端相机窗口和相机编号仅供案例参考，不作为通用平台正式协议。设备寻址、图像传输和协议冻结原则以[总体设计文档](总体设计文档.md)第 8 节为准。正式地址分配表在平台通信阶段另行发布，不允许把示例地址与未来通用映射同时解释为同一个协议版本。

本文件为业务协议规划，尚无实现。阶段 4 冻结 v1；阶段 1 先验证基础连接。Modbus 格式遵循[官方规范](https://www.modbus.org/modbus-specifications)。

## 1. 连接与功能码

- 仿真核心为服务端，C# 示例为客户端；默认监听 `127.0.0.1:1502`，允许配置网卡与端口。502 是标准端口，1502 是本项目开发默认值。
- 默认 Unit ID 为 1，超时建议 2000 ms，状态轮询 100 ms；服务端验证 Unit ID。
- 首版支持 03 读取保持寄存器、06 写单寄存器、16 写多个寄存器；未支持的功能码返回标准异常。
- 本文地址全部为 PDU 的十进制零基偏移。地址 0 对应部分工具显示的 40001，客户端必须明确地址模式。
- 每个寄存器内高字节先发送；32 位值使用高字在前；浮点采用 IEEE 754 Float32。业务浮点必须有限，不接受 NaN/Infinity。
- 机械长度 mm、角度 deg；位姿顺序 X、Y、Z、Rx、Ry、Rz，旋转约定见需求规格。
- TCP 处理必须支持拆包、粘包、MBAP 长度和事务标识校验；不能假设一次接收等于一条请求。

## 3. 命令与调度

| 命令码 | 含义 | 主要参数 |
| --- | --- | --- |
| 1 | MoveJ | 六关节目标、速度 |
| 2 | MoveL | 六维 TCP 目标、速度；首版使用当前工具与工件设置 |
| 3 | 移动到示教点 | 点位 ID、速度 |
| 10 | 运行积木程序 | 程序 ID；持外部控制权的委托执行 |
| 11 | 暂停当前动作/程序 | 无 |
| 12 | 继续 | 无 |
| 13 | 复位可恢复故障 | 无；不得自动启动动作 |
| 20 | 触发相机并执行配置的视觉流程 | 相机 ID，1 顶部/2 末端 |
| 30 | 设置数字输出 | DO 位掩码 |
| 40 | 启动/设置传送带 | 带速度；服从抓取与停止联锁 |
| 41 | 停止传送带 | 等待静止后完成 |
| 50 | 预留目标与工位槽位 | 目标 ID、工位/槽位、标定版本、来源帧 |
| 51 | 执行已预留目标的抓取 | 目标 ID，使用已校验抓取方案，完成需夹持确认 |
| 52 | 执行向预留工位的放置 | 目标/工位/槽位、末端相机帧、标定版本，完成需释放确认 |

取消通过独立寄存器 11 处理，使正在运动或忙时仍可停止。暂停/继续/复位作为控制命令，可在匹配状态下处理；其他动作一次只允许一个在途命令，不设置隐式动作队列。

上述动作队列与“传感器事件/候选目标队列”不同：事件采集独立运行，不能因运动 Busy 静默丢失光电事件。相机忙时按已配置策略有界排队或报告漏拍；满队列停带。传感器核心联锁可停止传送带，不能自行启动机器人运动。

50—52 是阶段 7 的高级任务接口，参数复用必须按命令类型校验。手动 MoveJ/MoveL 保留教学用途，不宣称任意手动动作具有自动抓放语义；高级任务必须验证标定、帧新鲜度、目标/槽位预留及夹具状态。抓取方案中的接近点、避障过渡点、容差和速度从工程读取。

## 4. 提交与完成握手

1. 连接，读版本与服务会话 ID，申请外部控制权并确认寄存器 3。非持有者可读状态，不能提交控制指令。
2. 用功能码 16 写待执行参数与命令码；暂存区只允许控制权持有连接写入，不触发执行。
3. 最后单独用功能码 16 写地址 102—103，提交一个非零 UInt32 序号。禁止半写提交序号。
4. 服务端在提交操作内原子冻结命令码和参数并校验。接受后更新接受序号/状态；拒绝时更新拒绝序号/原因且保留正在执行命令的状态。
5. 客户端等待接受序号匹配，再等待终态序号匹配，检查完成/失败/取消及错误码。TCP 写成功不代表运动完成。
6. 同一会话、同一控制连接内，重复最近已接受序号不重复执行；相同序号但负载不同则拒绝。序号单调递增，耗尽时重新建立会话，不能静默回绕。
7. 客户端超时先查询状态，不能自动使用新序号重发运动。断线重连或服务会话变化后，重新申请控制权并人工/应用逻辑核对当前状态，不能自动续跑。

控制权绑定连接；连接断开立即撤销控制权并发起约定停止。心跳默认每 500 ms 改变一次，2 s 不变触发控制失联；具体超时可配置。停止完成前拒绝新运动。

## 5. 一致性与视觉有效性

- 每个 03 响应必须从同一不可变状态快照编码；请求长度受 Modbus 标准限制，不能一次读取整个稀疏空间。
- 跨多次请求读取：先读快照序号，再读所需区域，再读快照序号；不一致则重试。刷新周期和重试上限应避免无限等待。
- 触发拍照后先使 Valid=0；图像、采样位姿和识别完成后原子更新结果。失败时 Valid 保持 0，错误码有效，禁止消费旧结果。
- 客户端必须核对 Frame ID、触发命令序号、标定状态、坐标系与分量有效位。需要的量无效时拒绝运动。
- 硬触发帧核对 Trigger ID；双相机同时核对 cameraId、标定集合版本、目标/工位 ID。停止前曝光的传送带定位结果在缺少有效补偿时不能用于停止后抓取。
- 图像路径/HTTP 端点在阶段 5 定义，不把整幅图像塞进寄存器。

## 6. 业务错误码建议

0 成功；1001 参数非法；1002 控制权冲突；1003 忙；1004 不可达；1005 关节越限；1006 奇异/数值失败；1007 碰撞；1101 指令超时；1102 心跳超时；1201 捕获失败；1202 检测失败；1203 标定无效；1204 图像/位姿不同步；1301 功能未实现；1302 重复序号负载冲突；1303 序号非法。

错误码与可恢复条件将在实现时补齐；保留 Modbus 标准异常用于非法功能码、地址和值等报文/寄存器层错误。

新增业务错误码：1401 目标已处理/已被预留；1402 工位满或槽位冲突；1403 未知/不匹配工位标志；1404 结果过期或带位移不匹配；1405 夹持确认失败；1406 释放确认失败；1407 触发队列满/漏拍；1408 传送带未静止；1409 标定版本不匹配。

## 7. C# 验收示例要求

最终提供 `Connect`、`AcquireControl`、`ReadState`、`MoveJAsync`、`MoveLAsync`、`TriggerVisionAsync`、`WaitForCompletionAsync`、`CancelAsync` 和释放控制权/连接的示例。异步接口必须支持 CancellationToken、超时、服务会话变化检测和浮点编码测试。

协议回归至少覆盖大小端、负角度、Float32 往返、TCP 拆粘包、半写提交、忙时拒绝、重复提交、断线、快照一致性与旧帧拒绝。

双相机抓放示例新增 Start/StopConveyor、ReadTrigger、ReserveTarget、PickTargetAsync、RecognizeStationAsync、PlaceTargetAsync；验证两个相机窗口不串帧，重复触发不重复抓取，未知标志/满位不放置。完整自动任务可委托本地积木，或由外部 C# 持控制权编排，二者不可同时控制。
