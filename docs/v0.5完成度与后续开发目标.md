# AxisLab v0.5 完成度与后续开发目标

状态基线：2026-10-21，AxisLab 0.5.0。依据阶段验收记录与分阶段实施计划整理，本次总结未重新执行测试。

## 当前定位

已交付通用仿真底座、相机拍照传图、Modbus/C# 外部控制及运动示教。现在可搭建场景，操作三轴/六轴机器人，拍摄与传出图像，保存和回放示教点。

阶段 0—5 已按各自验收范围完成；阶段 6—8 待实施，阶段 9 的桌面包装和部分说明资料已前置。各阶段工作量不同，不能用“已完成阶段数÷总阶段数”作为产品完成百分比。

用户最初设想的“自行标定 → 识别定位 → 光电触发 → 抓取 → 放到指定工位”完整教学场景尚待阶段 6—8 组合完成。

## 当前边界

- 编程仍通过界面操作、点位回放或外部 C# 完成；尚无积木编辑器与完整程序调试器。
- TCP、基座和工件坐标目前由用户输入；尚无采样向导、标定求解、独立验证与标定报告。
- 相机已能成像传图；棋盘格/工位标志检测、目标定位、畸变与噪声模拟尚未接入。
- 传送带、光电传感器、夹爪、工位占用和目标队列尚未实现为可添加设备。
- 碰撞采用简化代理；不包含自动绕障、精确接触、动力学或真实制动模拟。IK 和路径预检有计算预算。
- 示教回放逐点停稳，无路径融合；程序断点及暂停/继续将在程序运行时阶段处理。
- 发布为需 WebView2 Runtime 的便携目录；安装向导、签名、纯净机器完整安装及长时间综合场景验收尚待完成。

## 阶段 6：积木拖拽编程

目标：用户可用同一个流程组合机器人、相机、点位和逻辑指令，程序保存后可以重开执行。

建议分三步交付：

| 小阶段 | 开发目标 | 验收目标 |
| --- | --- | --- |
| 6A 编辑与保存 | Blockly 工作区；选择设备和示教点；运动、拍照、等待等基础块；稳定 ID 引用；参数校验；工程持久化 | 拖拽创建并保存程序，重开后内容与引用保持；缺失设备或点位有明确提示 |
| 6B 受控执行 | 积木编译为指令树；复用运动/相机接口；命令结果等待、超时、停止与控制权互斥 | 执行“到点 → 拍照 → 等待完成”；停止同时取消后续动作与等待，外部控制冲突能正确拒绝 |
| 6C 逻辑与调试 | 变量、条件、循环、结果引用；当前块高亮、单步、断点与执行日志 | 完成“到点 → 选相机拍照 → 判断成功 → 循环”；失败和停止可追溯，设备改名不失联 |

本阶段先使用拍照成功/失败等现有结果进行逻辑演示，识别坐标类积木在视觉功能完成后扩展。

## 阶段 7：视觉识别与标定训练

目标：用户自行采样、求解并验证坐标关系，能够用识别结果生成机器人目标。

| 小阶段 | 开发目标 |
| --- | --- |
| 7A | 标定板与基础标志成像、图像检测、相机内参标定；逐步加入一致的畸变与噪声模型 |
| 7B | TCP 标定、机器人基座相对参考系的注册、采样记录与质量提示 |
| 7C | 已知工作平面的像素到平面坐标映射及独立定位验证 |
| 7D | Eye-in-Hand：末端相机手眼标定、配对图像/机器人姿态、退化样本检查 |
| 7E | Eye-to-Hand：固定相机相对机器人基座的标定，以及工位/工件坐标与变换链 |

验收要求：仿真隐藏真值用于成像与评估；算法依据用户采集数据求解。用未参与拟合的样本验证，报告误差、退化原因和参数依赖；修改相关安装、内参、TCP 或几何后标定应失效。两台相机的数据和结果保持独立。

## 阶段 8：辅助设备与完整工作单元

目标：按需添加设备，复现用户最初提出的传送带与多工位抓放场景。

1. 8A：夹爪与教学抓放逻辑、抓取/释放确认。
2. 8B：传送带、光电传感器、边沿事件和相机硬触发仿真；事件链由核心执行。
3. 8C：工位标志、槽位、占用/预留、目标队列、去重与超时。
4. 8D：组合“光电来料 → 停带定位 → 坐标转换 → 抓取 → 识别目标工位 → 放置”。

首个完整案例采用停带定位抓取；连续运动跟踪抓取另行评估。验收覆盖至少三个工位、20 个任务，以及满位、未知标志、重复触发、识别/夹持失败；分别用积木和外部 C# 演示，无重复抓取或错误放置。

## 阶段 9：安装与教学交付

目标：在无开发环境的 Windows 机器按教程复现完整流程。

继续完成安装与更新方案、纯净机器测试、日志导出、示例课程、性能与容量记录，以及综合场景至少 30 分钟回归。已有桌面包装继续复用。
